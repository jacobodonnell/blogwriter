# Browser tests fail with "Uncaught SyntaxError: Unexpected strict mode reserved word" when JS bundle exceeds 8192 bytes

## Environment

- **pest-plugin-browser:** v4.3.0
- **PHP:** 8.4
- **Laravel:** 12

## Description

Browser tests throw a JavaScript syntax error when the application's compiled JS bundle is larger than 8KB. The error appears in the browser console during test runs:

```
Uncaught SyntaxError: Unexpected strict mode reserved word
```

This is misleading — the bundle itself is valid JavaScript. The problem is that the browser only receives the first 8192 bytes of the file, leaving it with truncated (and therefore invalid) JS.

## Steps to Reproduce

1. Create a Laravel 12 application with any JS bundle larger than 8KB (Alpine.js, React, Vue, etc. — the compiled output from a typical `npm run build` is enough).
2. Write a browser test that loads a page depending on that bundle.
3. Run the browser test suite.

The syntax error will appear consistently. If you strip the JS bundle down to under 8KB, the error disappears.

## Diagnostic Evidence

The JS file on disk is **63KB**. The browser receives exactly **8192 bytes** — a hard cutoff that matches the default chunk size for `fread` and `php://temp`.

Other asset types (CSS, images) load without issue.

## Where It Seems to Happen

The truncation appears to occur in `LaravelHttpServer::asset()`. For `.js` files, the method reads file content via `fread` into a `php://temp` stream, then passes that to `ReadableResourceStream` for serving. The non-JS path opens a real file descriptor and passes it directly to `ReadableResourceStream`, which works correctly.

The `php://temp` + `ReadableResourceStream` combination does not appear to deliver the full content to the client — only the initial chunk makes it through.

## Additional Notes

Happy to provide a minimal reproduction repo if that would help. The issue is reproducible with any standard Laravel + Vite setup where the compiled bundle exceeds 8KB.
